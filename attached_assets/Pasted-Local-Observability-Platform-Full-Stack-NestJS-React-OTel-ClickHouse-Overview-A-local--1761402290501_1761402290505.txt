Local Observability Platform — Full-Stack (NestJS + React + OTel + ClickHouse)
🏗 Overview

A local observability platform where:

NestJS Backend (Gateway) emits traces & logs (via OpenTelemetry SDK).

OpenTelemetry Collector in Kind (Kubernetes) receives OTLP data and exports directly to ClickHouse.

React (Vite) frontend displays telemetry via backend API.

Everything except the frontend runs inside Kind via Helm.

⚙️ Architecture
React (Vite)
   ↓
Backend (NestJS, OTel SDK)
   ↓
OTel Collector (Helm, Kind)
   ↓
ClickHouse (Helm, Kind)

🧩 Nx Monorepo Structure
apps/
  backend/          → NestJS API (instrumented with OpenTelemetry)
  frontend/         → React + Vite UI
infra/
  charts/           → Helm charts for backend, collector, clickhouse
  kind/             → Kind cluster config

🧰 Yarn Scripts (Automation for Local Dev)

Add these to your root package.json:

{
  "scripts": {
    "kind:create": "kind create cluster --name observability --config infra/kind/kind-config.yaml",
    "kind:load:backend": "docker build -t local/backend:latest apps/backend && kind load docker-image local/backend:latest --name observability",
    "kind:load:otel": "docker build -t local/otel-collector:latest -f infra/otel/Dockerfile . && kind load docker-image local/otel-collector:latest --name observability",
    "kind:load:all": "yarn kind:load:backend && yarn kind:load:otel",
    "helm:deps": "helm dependency update infra/charts/observability",
    "helm:deploy": "helm upgrade --install observability infra/charts/observability --namespace observability --create-namespace",
    "helm:delete": "helm uninstall observability -n observability",
    "cluster:up": "yarn kind:create && yarn kind:load:all && yarn helm:deps && yarn helm:deploy",
    "cluster:down": "yarn helm:delete && kind delete cluster --name observability",
    "port:backend": "kubectl port-forward svc/backend 3001:3001 -n observability",
    "port:clickhouse": "kubectl port-forward svc/clickhouse 8123:8123 -n observability",
    "dev:frontend": "nx serve frontend",
    "dev:backend": "nx serve backend",
    "up": "yarn cluster:up && yarn port:backend",
    "down": "yarn cluster:down"
  }
}

🚀 Development Workflow

Start Local Cluster

yarn cluster:up


→ builds Docker images
→ loads them into Kind
→ installs Helm chart
→ deploys backend, collector, clickhouse

Run Frontend

yarn dev:frontend


→ connects to http://localhost:3001 (port-forwarded backend)

Access ClickHouse (optional)

yarn port:clickhouse


→ available at http://localhost:8123

Tear Down

yarn cluster:down

🔁 Data Flow
Frontend → Backend → OTel Collector → ClickHouse


Backend auto-instrumented with OTel SDK (HTTP + logs)

Collector receives OTLP on 4317/4318

Collector exports traces & logs directly to ClickHouse (9000)

Frontend queries backend for persisted telemetry

✅ Example OTel Collector Config
receivers:
  otlp:
    protocols:
      grpc:
      http:
exporters:
  clickhouse:
    endpoint: tcp://clickhouse:9000
    database: otel
    traces_table_name: otel_traces
    logs_table_name: otel_logs
service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [clickhouse]
    logs:
      receivers: [otlp]
      exporters: [clickhouse]
